=== 2. METRIQUES -- CORRIGEES ET SEPAREES ===
`fact_decode_ms` etait TROMPEUR : il ne dit pas ce qu'il mesure. Sur le chemin
texte il couvre le decodage du fait, sur le chemin `state_ref` il couvre
l'import. Des champs separes ont ete ajoutes (`preparation_total_ms`,

avec la convention **-1 = NON MESURE**, jamais un zero implicite.
`fact_decode_ms` est CONSERVE pour compatibilite.

DEFAUT REEL CORRIGE : sur `extract_only`, la branche envoyait le resultat et
`break` AVANT le calcul de la metrique, qui restait donc a sa valeur par defaut
**0.0** -- indistinguable d'une mesure reelle nulle. Les anciennes reponses sont
CONSERVEES comme preuves historiques dans RAW_RESPONSES.txt, et gardent ce 0.0.
Dans la mesure courante, A rapporte toujours `fact_decode_ms:0.0` : **le
correctif de separation des metriques est en place mais A sort encore avant**,
et je le declare plutot que de le masquer.

**COUT MESURE DE L'INTEGRITE** : avec le SHA256 en place, `fact_decode_ms` sur
RESTORED est passe de **74.266 ms** (SERVER-CACHE-PROOF-05, sans SHA256) a
**216.987 ms** (ici, avec SHA256 sur 160 697 024 octets), soit **+142.7 ms**.
Ce n'est pas un gain : hacha 160 Mo coute ~143 ms. Je le publie comme un COUT.

=== 3. COMPATIBILITE -- RACCORDEE, MAIS REFUS NON EXERCE ===
COMPATIBILITY_CHECK_CONNECTED=YES
  Un manifeste est desormais ASSOCIE au blob (`kv_state_manifest`) et VERIFIE
  AVANT `set_data`. Il porte, derives du code : description + taille + nombre de
  parametres + topologie du modele (n_vocab, n_layer, n_embd) ; identite du
  calcul Q1 (SHA256 de la libllama REELLEMENT chargee, lue dans /proc/self/maps) ;
  format du blob (`io_magic` 0xaf143cd9) ; types KV ; mode de serialisation
  (`OBRAIN_STATE_TYPE`) ; configuration de contexte (n_ctx, n_batch, n_ubatch,
  n_seq_max) ; convention de sequence (seq_id) ; **prefixe exact** (jusqu'a 4096
  IDs) ; positions min/max.
  **SHA256** des octets stockes, calcule a l'extraction et re-verifie avant
  import. **Toute donnee necessaire INCONNUE refuse l'import** : un manifeste
  incomplet (`complete()==false`) est refuse, jamais « compatible par defaut ».
  La reference FNV ne remplace PAS ces controles : elle indexe, elle ne qualifie
  pas.

INCOMPATIBLE_STATE_REFUSED_BEFORE_IMPORT=NOT_RUN
  **Je n'ai PAS exerce le refus.** Aucun etat incompatible, aucun blob tronque,
  aucun SHA256 altere, aucun manifeste incomplet n'a ete soumis.
  Ce que la mesure actuelle ETABLIT : l'import de C a REUSSI *avec* le controle
  actif, donc le manifeste produit a l'extraction est COHERENT avec la
  configuration courante, et le SHA256 verifie correspond. **C'est une
  confirmation du chemin nominal, PAS un test du chemin de refus.**
  Un code compile n'est pas un test execute : je ne le declare pas PASS.

CONSEQUENCE DECLAREE : le repli disque (K1b) charge un blob **sans manifeste**
et sera desormais **REFUSE** avec « state has NO compatibility manifest ». C'est
conforme a l'exigence (donnee necessaire inconnue -> refus), mais cela **ferme
le chemin disque** tant qu'un manifeste n'est pas persiste avec le blob. Non
verifie ici, car le chemin memoire a repondu.
